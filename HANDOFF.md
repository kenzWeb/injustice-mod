# HANDOFF — контекст проекта для агента на новой машине

Читай этот файл первым. Он заменяет переписку, в которой всё это делалось.
Задача на сборку — в [PROMPT.md](PROMPT.md).

## Что это

Твик-меню для **Injustice 2 Mobile 6.7.1 (iOS)** на джейлбрейкнутом устройстве
владельца. Цель — видеть HP в бою автоматически, без ручного поиска значений
сканером памяти, плюс пара переключателей.

Всё, что здесь есть, получено **статическим анализом** расшифрованного бинаря.
Никаких догадок в офсетах нет: каждый выведен из дизассемблера, ниже указано
откуда.

## Целевой бинарь

| | |
|---|---|
| Путь в IPA | `Payload/Injustice2Mobile.app/Injustice2Mobile` |
| Формат | Mach-O 64, `MH_EXECUTE`, **ARM64** (arm64e-слайса нет) |
| Размер | 98 МБ, `__text` 66 МБ |
| Шифрование | снято, `LC_ENCRYPTION_INFO_64.cryptid = 0` |
| UUID | `2c66bd15-78e2-3cab-b3f6-2be3ff279a18` |
| Bundle ID | `com.wb.Injustice.Brawler2017` |
| CFBundleVersion | `1438123`, short `6.7.1` |
| Image base | `0x100000000` |
| Движок | **Unreal Engine 4 (~4.27)**, не Unity — IL2CPP-метаданных нет |

Важная особенность: сегмент `__TEXT` начинается с `vmaddr 0x100000000, fileoff 0`,
поэтому **RVA численно равен файловому смещению**. Удобно для патчеров.

Символы C++ и RTTI вырезаны полностью — из 3879 записей symtab только 613
определённых, все из сторонних ObjC-SDK.

## Откуда взялись имена и офсеты

Аналогом `Il2CppDumper` для UE служат статические таблицы рефлексии
`UECodeGen_Private` в `__DATA_CONST,__const` плюс восстановление аргументов
на вызовах `GetPrivateStaticClassBody` (`0x102531110`, 4661 вызов). Оттуда
получены 3714 `UClass` с размерами и суперклассами, 2760 `UScriptStruct`,
1425 `UEnum`, 11183 `UFunction` (9670 с адресами нативных exec-функций) и
29016 смещений полей.

Инструменты и выгрузка **остались на исходной Windows-машине** в
`dump/tools` и `dump/out` — в этот репозиторий они не клались, для сборки
твика не нужны. Если понадобятся, их надо запросить у владельца.

## Ключевая находка

**HP не является `UPROPERTY`** — в таблицах рефлексии его нет, только геттеры.
Офсеты сняты из самих геттеров.

`ACombatCharacter` (размер `0x1DC0`), наследование
`ACombatCharacter : ABaseGameCharacter : ACharacter : APawn : AActor : UObject`:

| Офсет | Тип | Что | Источник |
|---|---|---|---|
| `+0x4E4` | int32 | CurrentHealth | `GetHealthPercentage` RVA `0x1B4CFB4` |
| `+0x4E8` | int32 | MaxHealth | там же |
| `+0x1240` | int32 | BaseHealth | `execGetBaseHealth` RVA `0x210D978` |
| `+0x1244` | int32 | BaseModifiedHealth | RVA `0x210D924` |
| `+0x1248` | int32 | AdditiveModificationsHealth | RVA `0x210D8D0` |

`GetHealthPercentage` грузит оба поля как `ldr s0` + `scvtf` — то есть в памяти
это **знаковые int32**, а не float. Для сканера памяти тип поиска — Dword.

### Точка перехвата

**RVA `0x1B50954` = `ACombatCharacter::SetCurrentHealth(int32)`**, `x0` = объект,
`w1` = новое HP:

```
ldr  w8, [x0, #0x4e8]     ; MaxHealth
cmp  w1, w8
csel w8, w1, w8, lt       ; min(new, max)
cmp  w1, #0
csel w8, wzr, w8, lt      ; clamp к 0
str  w8, [x0, #0x4e4]     ; <- единственная запись CurrentHealth
bl   ...                  ; нотификации, проверка смерти, UI
```

Через неё проходят **все** изменения HP: урон, хил, инициализация боя. Прямых
`str w,[x,#0x4E4]` в бинаре всего 13, и 12 из них принадлежат другим классам с
совпавшим офсетом — эта единственная релевантная. Поэтому один хук видит всё.

### Как отличается свой персонаж от чужого

`ABaseGameCharacter::IsPlayerCharacter()` — **виртуальный**, слот vtable по
байтовому смещению `0x9A0` (из `execIsPlayerCharacter`: `ldr x8,[x0]` →
`ldr x8,[x8,#0x9a0]` → `blr x8`). Вызывается через vptr самого объекта.

Тупик, который уже проверен и отброшен: `CharacterTeam` (`+0x118C`) — это
**фракция ростера** (`JusticeLeague`, `SuicideSquad`, `MortalKombat`, …), а не
сторона боя. Для «свой/чужой» не годится.

## Решения в коде и почему

1. **Один хук вместо патча инструкций.** Патчер офсетов (у владельца есть такой
   в тулзе) умеет только писать байты в код — показать значения он не может в
   принципе. Хук даёт и чтение, и подмену.
2. **Никаких обращений к файловой системе.** У владельца **RootHide** с
   рандомизированным jbroot; любой хардкод путей ломается. Настройки живут в
   памяти (атомики), prefs-plist и ресурсов бандла нет. Благодаря этому код
   одинаков для roothide/rootless/rootful — различается только упаковка.
3. **UI не разыменовывает указатели на персонажей.** Значения копируются в
   атомики внутри хука; иначе оверлей падал бы на устаревшем объекте после
   конца боя. Через 3 с без вызовов показывает `--`.
4. **Version lock.** `%ctor` читает `CFBundleVersion` и при несовпадении с
   `1438123` не ставит хуки вообще — чтобы не писать по чужим адресам после
   обновления игры.
5. **`Freeze HP (все)`** намеренно грубый: останавливает запись у всех, бой не
   закончится. Оставлен для наблюдения, не для игры.

## Статус

Сделано:

- полный статический дамп UE-рефлексии (на Windows-машине)
- офсеты и семантика функций **проверены по бинарю**
- твик написан, залит в этот репозиторий

Не сделано:

- **твик ни разу не компилировался** — на исходной машине была Windows, а
  сборка iOS-твика требует macOS либо Linux с тулчейном. Попытка через Docker
  провалилась: движок Docker не резолвил DNS до registry. Это и есть текущая
  задача.
- на устройстве не запускался, поведение UI не проверено
- `GWorld` / `GUObjectArray` / `FNamePool` не искались — для статического дампа
  и для этого хука не нужны
- ассеты в `cookeddata/.../paks` (1.6 ГБ) не распаковывались — Blueprint-классы
  живут там, а не в бинаре

## Если игра обновится

Все RVA слетят. Порядок пересчёта описан в [README.md](README.md); коротко:

1. заново снять дамп (`dump/tools/emit.py` на исходной машине);
2. найти `SetCurrentHealth` — искать в `__text` инструкцию
   `str w, [x, #<CurrentHealth>]` внутри функции, которая ещё и грузит
   `+<MaxHealth>` и клампит двумя `csel` (скрипт `find_hp_sites2.py`);
3. слот `IsPlayerCharacter` — дизассемблировать `execIsPlayerCharacter` и
   прочитать смещение в `ldr x8, [x8, #...]`;
4. обновить `kExpectedBundleVersion`.

# HANDOFF — контекст проекта для агента на новой машине

Читай этот файл первым. Он заменяет переписку, в которой всё это делалось.
Задача на сборку — в [PROMPT.md](PROMPT.md).

## Что это

Твик-меню для **Injustice 2 Mobile 6.7.1 (iOS)** на джейлбрейкнутом устройстве
владельца. Цель — видеть HP в бою автоматически, без ручного поиска значений
сканером памяти, плюс пара переключателей.

Всё, что здесь есть, получено **статическим анализом** расшифрованного бинаря.
Никаких догадок в офсетах нет: каждый выведен из дизассемблера, ниже указано
откуда.

## Целевой бинарь

| | |
|---|---|
| Путь в IPA | `Payload/Injustice2Mobile.app/Injustice2Mobile` |
| Формат | Mach-O 64, `MH_EXECUTE`, **ARM64** (arm64e-слайса нет) |
| Размер | 98 МБ, `__text` 66 МБ |
| Шифрование | снято, `LC_ENCRYPTION_INFO_64.cryptid = 0` |
| UUID | `2c66bd15-78e2-3cab-b3f6-2be3ff279a18` |
| Bundle ID | `com.wb.Injustice.Brawler2017` |
| CFBundleVersion | `1438123`, short `6.7.1` |
| Image base | `0x100000000` |
| Движок | **Unreal Engine 4 (~4.27)**, не Unity — IL2CPP-метаданных нет |

Важная особенность: сегмент `__TEXT` начинается с `vmaddr 0x100000000, fileoff 0`,
поэтому **RVA численно равен файловому смещению**. Удобно для патчеров.

Символы C++ и RTTI вырезаны полностью — из 3879 записей symtab только 613
определённых, все из сторонних ObjC-SDK.

## Откуда взялись имена и офсеты

Аналогом `Il2CppDumper` для UE служат статические таблицы рефлексии
`UECodeGen_Private` в `__DATA_CONST,__const` плюс восстановление аргументов
на вызовах `GetPrivateStaticClassBody` (`0x102531110`, 4661 вызов). Оттуда
получены 3714 `UClass` с размерами и суперклассами, 2760 `UScriptStruct`,
1425 `UEnum`, 11183 `UFunction` (9670 с адресами нативных exec-функций) и
29016 смещений полей.

Инструменты и выгрузка **остались на исходной Windows-машине** в
`dump/tools` и `dump/out` — в этот репозиторий они не клались, для сборки
твика не нужны. Если понадобятся, их надо запросить у владельца.

## Ключевая находка

**HP не является `UPROPERTY`** — в таблицах рефлексии его нет, только геттеры.
Офсеты сняты из самих геттеров.

`ACombatCharacter` (размер `0x1DC0`), наследование
`ACombatCharacter : ABaseGameCharacter : ACharacter : APawn : AActor : UObject`:

| Офсет | Тип | Что | Источник |
|---|---|---|---|
| `+0x4E4` | int32 | CurrentHealth | `GetHealthPercentage` RVA `0x1B4CFB4` |
| `+0x4E8` | int32 | MaxHealth | там же |
| `+0x1240` | int32 | BaseHealth | `execGetBaseHealth` RVA `0x210D978` |
| `+0x1244` | int32 | BaseModifiedHealth | RVA `0x210D924` |
| `+0x1248` | int32 | AdditiveModificationsHealth | RVA `0x210D8D0` |

`GetHealthPercentage` грузит оба поля как `ldr s0` + `scvtf` — то есть в памяти
это **знаковые int32**, а не float. Для сканера памяти тип поиска — Dword.

### Функции боя

Все адреса — RVA настоящих нативных функций, а не exec-переходников. Переходник
ловит только вызовы из Blueprint, поэтому для каждой функции адрес доставался
дизассемблированием exec и взятием последнего «не-хелперного» `bl`.

| RVA | Функция | Как получен |
|---|---|---|
| `0x1B50954` | `ACombatCharacter::SetCurrentHealth(int32)` | поиск `str w,[x,#0x4E4]` в функции с двумя `csel` |
| `0x1B4CFB4` | `ACombatCharacter::GetHealthPercentage()` | exec `0x210AFF4` → `bl` |
| `0x1B4D8D8` | `ACombatCharacter::ShowDamageMessage(float, ...)` | exec `0x2110D00` → `bl` |
| `0x1B4062C` | `ACombatCharacter::TakeCombatDamage(float, float, ...)` | exec `0x210B560` → `bl` |
| `0x1B57088` | `ACombatCharacter::DamageCharacter(ACombatCharacter*, float, ...)` | exec `0x210B70C` → `bl` |

### Энергия и стоимость приёмов

Power и Energy **не поля персонажа** — они живут в компонентах
`UCombatCharacterPower` / `UCombatCharacterEnergy` (оба наследуют
`UCombatCharacterResource`, размер `0x128`).

Layout компонента подтверждён напрямую, `x0` в exec — это сам ресурс:

| Офсет | Что | Источник |
|---|---|---|
| `+0xF8` | текущее значение (float) | лист-функция `0x3745874`: `ldr s0,[x0,#0xF8]; ret` |
| `+0xFC` | максимум (float) | `execGetMaxResource 0x211ED20`: `ldr s0,[x0,#0xFC]` |

**Важное предупреждение о ложном следе.** В `ResourceComponent::GetCurrent`
(`0x1B7C83C`) видно `ldr x8,[x0,#0xB00]` / `#0xB08`, а в энергетическом
аналоге `0x1B7CBD8` — `#0xBB0` / `#0xBB8`. Соблазн принять их за смещения
компонентов внутри `ACombatCharacter` — ошибка: до этой функции `x0` дважды
преобразуется вызовами, и это уже не персонаж. Проверка по дампу подтверждает:
по `+0xB00` у `ACombatCharacter` лежит `ShieldBreakerParticleData`, а не
указатель. Поэтому твик **не ходит по этим указателям**, а хукает методы
персонажа, где `x0` гарантированно `ACombatCharacter`.

Гейты приёмов (все `bool f(ACombatCharacter*, ECombatAttackType)`):

| RVA | Функция |
|---|---|
| `0x1B4E914` | `HasEnoughFundsForSpecialAbility` |
| `0x1B4E874` | `HasEnoughPowerForSpecialAbility` |
| `0x1B4E8C4` | `HasEnoughEnergyForSpecialAbility` |
| `0x1B457A0` | `HasEnoughResourceForSpecialAbility` |
| `0x1B4DEA8` | `float GetPowerPercentage(ECombatAttackType)` |
| `0x1B4E0F0` | `float GetCurrentPower()` |
| `0x1B4E110` | `float GetCurrentEnergy()` |

Приёмы в этой игре ограничены **стоимостью ресурса, а не таймером**, поэтому
снятие гейта убирает и «ожидание между приёмами» — отдельного кулдауна нет.

### Встроенные читы разработчиков

В релизной сборке остался `UCombatCheatManager` (94 функции): `CheatWin`
`0x211F2AC`, `CheatKillAI`, `CheatToggleUnlimitedPlayerSpecials`,
`CheatSetHealth` и прочие. Все exec-переходники сначала зовут `0x2121D80`,
затем tail-call в реальную реализацию (`CheatWin` → `0x1B417D8`).

**Не используются намеренно.** Для их вызова нужен живой экземпляр
`UCheatManager`, который UE создаёт не во всех конфигурациях, а это не
проверено. Авто-победа сделана через уже работающий хук `SetCurrentHealth`,
то есть противник умирает штатным путём игры, без зависимости от наличия
чит-менеджера.

Состав по категориям: матч/бой 7, HP и урон 23, энергия и суперы 17,
поведение ИИ 24, неуязвимость 4, отладка и HUD 17. Полезны как карта того,
какие рычаги в бою вообще существуют — многие функции указывают на
соответствующие обычные методы `ACombatCharacter`, которые и хукаются.

### Заморозка ИИ

`ACombatCharacter::IsStunned(EStunType)` — реальный адрес `0x1B490F8`
(exec `0x210C830`), `bool`, `x0` = персонаж. Хук возвращает `true` для
не-игроков: оглушённый персонаж не действует, но остаётся уязвимым.

`IsFrozen()` (`0x1B47CD0`) намеренно не трогается — заморозка в этой игре
влияет и на возможность попадания по цели, а не только на её действия.

ABI `ShowDamageMessage` проверен по прологу: `x0` = жертва, **`s0` = величина
урона** (`fmov s8, s0`, затем `fcvtzs w24, s8` для показа), `x1` = `&DamageEvent`,
`x2` = `DamageCauser`, `w3` = IsCrit, `w4` = IsLethalHit, `w5` = bTrueDamage.

Почему хукаются две функции, а не одна: `SetCurrentHealth` меняет HP, но
всплывающая цифра урона считается отдельно и раньше — если править только HP,
на экране показывается неизменённое число. Обе точки берут решение из одного
модуля `IMDamage`, поэтому разойтись не могут.

### Точка перехвата

**RVA `0x1B50954` = `ACombatCharacter::SetCurrentHealth(int32)`**, `x0` = объект,
`w1` = новое HP:

```
ldr  w8, [x0, #0x4e8]     ; MaxHealth
cmp  w1, w8
csel w8, w1, w8, lt       ; min(new, max)
cmp  w1, #0
csel w8, wzr, w8, lt      ; clamp к 0
str  w8, [x0, #0x4e4]     ; <- единственная запись CurrentHealth
bl   ...                  ; нотификации, проверка смерти, UI
```

Через неё проходят **все** изменения HP: урон, хил, инициализация боя. Прямых
`str w,[x,#0x4E4]` в бинаре всего 13, и 12 из них принадлежат другим классам с
совпавшим офсетом — эта единственная релевантная. Поэтому один хук видит всё.

### Как отличается свой персонаж от чужого

`ABaseGameCharacter::IsPlayerCharacter()` — **виртуальный**, слот vtable по
байтовому смещению `0x9A0` (из `execIsPlayerCharacter`: `ldr x8,[x0]` →
`ldr x8,[x8,#0x9a0]` → `blr x8`). Вызывается через vptr самого объекта.

Тупик, который уже проверен и отброшен: `CharacterTeam` (`+0x118C`) — это
**фракция ростера** (`JusticeLeague`, `SuicideSquad`, `MortalKombat`, …), а не
сторона боя. Для «свой/чужой» не годится.

## Архитектура

Код разбит по слоям, комментариев в исходниках нет намеренно — вся справочная
информация собрана здесь.

```
Tweak.xm            только %ctor: инициализация, проверка версии, установка хуков
src/Offsets.h       все RVA и смещения полей
src/IMRuntime       база образа, RVA→указатель, IsPlayerCharacter, чтение HP
src/IMSettings      всё состояние мода за атомарным API, без UIKit
src/IMDamage        чистая логика: решение по HP и по показываемой цифре
src/IMHooks         тела хуков и их установка
src/IMTheme         цвета, шрифты, метрики
src/IMRowBuilder    конструктор строк меню (тумблер, значение, кнопка, подпись)
src/IMOverlayWindow окно с passthrough hitTest
src/IMMenu          сборка и поведение меню
```

Зависимости идут строго в одну сторону: UI знает про `IMSettings`, хуки знают
про `IMSettings`, `IMDamage` и `IMRuntime`, но `IMDamage` не знает ни про UIKit,
ни про хуки. Благодаря этому решение об уроне принимается ровно в одном месте.

### Обязательное: `extern "C"` в заголовках для `Tweak.xm`

Theos компилирует `.xm` как **Objective-C++**, а весь `src/` — обычный
Objective-C. Голое объявление C-функции в заголовке, включённом из `Tweak.xm`,
попадает в C++-namespace и манглится (`IMHooksInstall()`), тогда как
определение в `.m` даёт C-символ (`_IMHooksInstall`). Линковка падает с
`Undefined symbols ... NOTE: found '_IMHooksInstall' ... declaration possibly
missing 'extern "C"'`.

Поэтому `IMHooks.h`, `IMRuntime.h`, `IMSettings.h`, `IMMenu.h` оборачивают
объявления функций в:

```c
#ifdef __cplusplus
extern "C" {
#endif
...
#ifdef __cplusplus
}
#endif
```

**Любой новый заголовок, включаемый из `Tweak.xm`, обязан делать то же самое.**
`@interface` ObjC-классов оставляют снаружи блока — им это не нужно.
`Offsets.h` не требует обёртки (одни макросы). Остальные заголовки
(`IMDamage.h`, `IMPresets.h`, `IMTheme.h`, `IMRowBuilder.h`,
`IMOverlayWindow.h`) включаются только из `.m`, смешения линковок нет.

До версии 1.1.0 проблемы не было, потому что весь код лежал в одном `Tweak.xm`.

### ARC и out-параметры

Не возвращать паттерн «out-параметр — указатель на ObjC-объект» без явного
`__strong`. Под ARC указательный out-параметр по умолчанию `__autoreleasing`,
и передача `&_ivar` (адрес `__strong` ivar) запрещена: `passing address of
non-local object to __autoreleasing parameter for write-back`. Если такой
параметр нужен, тип обязан быть `UITextField * __strong *`.

## Решения в коде и почему

1. **Один хук вместо патча инструкций.** Патчер офсетов (у владельца есть такой
   в тулзе) умеет только писать байты в код — показать значения он не может в
   принципе. Хук даёт и чтение, и подмену.
2. **Никаких обращений к файловой системе.** У владельца **RootHide** с
   рандомизированным jbroot; любой хардкод путей ломается. Настройки живут в
   памяти (атомики), prefs-plist и ресурсов бандла нет. Благодаря этому код
   одинаков для roothide/rootless/rootful — различается только упаковка.
3. **UI не разыменовывает указатели на персонажей.** Значения копируются в
   атомики внутри хука; иначе оверлей падал бы на устаревшем объекте после
   конца боя. Через 3 с без вызовов показывает `--`.
4. **Version lock.** `%ctor` читает `CFBundleVersion` и при несовпадении с
   `1438123` не ставит хуки вообще — чтобы не писать по чужим адресам после
   обновления игры.
5. **`Freeze HP (все)`** намеренно грубый: останавливает запись у всех, бой не
   закончится. Оставлен для наблюдения, не для игры.
6. **Все модификаторы применяются только при `delta > 0`**, то есть когда HP
   реально уменьшается. Это не косметика: `SetCurrentHealth` вызывается и при
   инициализации боя, и раньше `One-hit kill` обнулял противника ещё до начала
   матча — тот стоял с 0 HP, не бил и не получал урона.

## Статус

Сделано и **проверено на устройстве**:

- полный статический дамп UE-рефлексии (остался на Windows-машине)
- офсеты и семантика функций проверены по бинарю
- твик собран на macOS, установлен через Sileo, хук работает, HP читается
- `1.0.1` — фикс: оверлей перехватывал все касания и игра была некликабельна
  (`IMPassthroughWindow.hitTest:`); без него игра идёт фоном со звуком, но не
  реагирует ни на один тап
- `1.0.2` — переработан UI, множители урона, восстановление HP, Master OFF

Не сделано:

- `GWorld` / `GUObjectArray` / `FNamePool` не искались — для статического дампа
  и для этого хука не нужны
- ассеты в `cookeddata/.../paks` (1.6 ГБ) не распаковывались — Blueprint-классы
  живут там, а не в бинаре
- **обход античита не делался и делаться не будет.** `Master OFF` — это не
  маскировка, а просто мгновенный возврат к ванильному поведению без удаления
  пакета

## Если игра обновится

Все RVA слетят. Порядок пересчёта описан в [README.md](README.md); коротко:

1. заново снять дамп (`dump/tools/emit.py` на исходной машине);
2. найти `SetCurrentHealth` — искать в `__text` инструкцию
   `str w, [x, #<CurrentHealth>]` внутри функции, которая ещё и грузит
   `+<MaxHealth>` и клампит двумя `csel` (скрипт `find_hp_sites2.py`);
3. слот `IsPlayerCharacter` — дизассемблировать `execIsPlayerCharacter` и
   прочитать смещение в `ldr x8, [x8, #...]`;
4. обновить `kExpectedBundleVersion`.
